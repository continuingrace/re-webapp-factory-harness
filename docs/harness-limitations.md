# RE Webapp Factory Harness — 알려진 한계와 미검증 범위

이 문서는 공개판에도 포함되는 일반 한계만 모은다. 확인하지 않은 것은 통과로 보지 않는다.
세부 검증 기록은 [harness-verification.md](harness-verification.md), 리뷰 기록은 [harness-review.md](harness-review.md)에 있다.

## 1. hook

- project·agent hook(`scripts/hook-guard.mjs`)은 완전한 OS sandbox가 아니다. 알려진 쓰기 동사·redirect·Git 파괴 명령·local 설정 경로·역할 전용 스크립트 실행을 문자열로 판정하는 방어선이다.
- 쓰기 동사 목록 밖의 명령은 판정하지 않는다. 예: `find … -delete`, `node -e`로 하는 파일 조작, `tar -x`, `rsync`, `robocopy`, 스크립트 파일 내부의 쓰기. 이 경우의 주 방어선은 subagent의 제한된 도구, 역할별 정확한 명령 allowlist, 판정 스크립트의 fingerprint·경로 검증이다.
- 셸보다 넓게 판정하므로 정상 명령도 막을 수 있다(승인된 오탐).
  - 보호 폴더 이름과 일치할 수 있는 glob 삭제 (`rm -rf node_modules/*`)
  - 쓰기 동사 인자·redirect 대상에 `$`·`%X%` 같은 실행 시 값이 있는 명령
  - 가능한 작업 위치 집합에 시작 위치가 남아서 생기는 상위 경로 판정 (`cd docs/sub && rm -rf ..`)
  - glob·변수로 이동하거나 `cd -`·`popd` 뒤의 상대경로 삭제·이동, `cwd`가 없는 hook 입력의 상대경로 삭제·이동
  - 역할 전용 스크립트 경로 문자열이 들어간 읽기 명령·heredoc
- hook 입력의 `cwd`가 셸의 실제 작업 위치와 같다고 전제한다.

## 2. 검증 상태

| 범위 | 상태 |
|---|---|
| 실제 HTTPS 운영 URL에서의 4단계 성공 경로 (실제 TLS·DNS·redirect) | `NOT_RUN` — 모의 resolver·transport의 합성 결과만 확인 |
| 실제 모바일 기기 검수·홈 아이콘 승인·최종 승인이 들어간 5단계 end-to-end | `NOT_RUN` |
| 실제 `COMPLETE` 전이 | `NOT_RUN` — 모의 응답을 쓰는 판정 단위 테스트로만 확인 |
| Node.js 20에서의 `npm test` | `NOT_RUN` — Node.js 24에서만 실행 |
| 다른 OS용 선택 의존성(`package-lock.json`) 대조 | `NOT_RUN` |

## 3. 판정과 evidence

- scheme 없는 상대 URL(`/api?token=…`)과 값 없는 query 키는 evidence 마스킹 대상이 아니다.
- evidence 문자열은 200자에 말줄임표 1자가 붙을 수 있고, 콘솔 메시지 개수 상한이 없다.
- `policies.zero_targets.applies_to`는 문서 역할이며 코드가 직접 읽지 않는다.
- 4단계 재실행 회귀 테스트는 합성 결과로 검증했고, 실제 4단계 실행 경로 전체는 통합 테스트하지 않았다.
- 흐름 테스트가 중간에 실패하면 공유 `releases/` 정리가 남아 뒤 테스트가 연쇄 실패할 수 있다.
- 브라우저 테스트의 임시 프로필 경쟁을 피하려고 `npm test`는 테스트 파일을 순서대로 실행한다.

## 4. 비공개 식별자 설정

- 자동 테스트는 fixture 식별자만 쓴다. 실제 식별자가 추적 파일에 없는지는 별도 도구로 확인한다.
- 길이 0 regex 거부는 빈 문자열과 몇 개의 probe 문자열로 하는 보조 방어이며 완전한 증명이 아니다. 스캔 중 길이 0 일치가 나오면 확인 필요로 멈춘다.
- regex 성능(과도한 백트래킹)은 사용자가 정한 설정 값의 책임이며 시간 제한이 없다.
- 식별자 검사(ST-04) evidence의 경로만 식별자 부분을 가린다.
- 설정 해시를 기록하지 않는다. 판정 결과가 같게 나오는 설정 변경은 감지하지 않는다.

## 5. public export

- 공개판은 지정 commit의 추적 파일을 내용 변환 없이 allowlist 기준으로 복사한다. 원본에 남은 문제는 고쳐서 새 commit으로 다시 내보내야 한다.
- 검사 규칙과 local 설정은 export 시점 작업 트리의 것을 쓴다. 같은 commit이라도 규칙이 강화되면 이전에 통과한 export가 실패할 수 있다(의도한 동작).
- 개인 절대경로 기본 패턴은 `Users`·`Documents and Settings`·`home` 아래 사용자 폴더 형태만 잡는다. 그 밖의 드라이브·경로는 local 차단 목록에 의존한다.
- 비밀 패턴은 판정 기준의 정해진 형식(토큰 접두사·개인키 블록 등)만 잡는다.
- 공개 이력 대응표의 commit SHA는 앞 7자리로 찾는다.
- 외부 참고 자료 출처 표기는 `policies.public_export.attribution_exemptions`에 내용 해시로 고정한 한 파일·한 줄에서만 local 차단 목록 검사를 건너뛴다. 비밀·개인키·개인 경로·commit SHA·비공개 식별자 검사는 그 줄에도 적용되고, 다른 위치·수정된 줄·중복된 줄은 막는다.

## 6. 외부 디자인 참고 자료

[design.md](design.md)는 공개 외부 디자인 참고 자료를 참고해 RE Webapp Factory 관리 화면에 맞게 재구성한 문서다. `[제공 기준]`으로 표시한 항목은 참고 자료의 설계 수치·원칙을 참고한 것이다.

- 참고 출처: Huddling Club 공개 자료 — https://huddling.ai/
- 이 저장소는 비상업적 개인 실험이다.
- 원 자료의 권리는 원 제공자에게 있으며, 이 저장소는 소유권을 주장하지 않는다.
- 원 자료의 파일·코드·이미지·Figma·폰트·문서 원문은 포함하지 않는다.

| 대상 | 결과 |
|---|---|
| 원 자료의 파일·코드·이미지·폰트·Figma 산출물·문서 원문 | 미포함 (`NOT_APPLICABLE`). 공개판 파일 전체를 확인한 범위에서 포함되지 않았다. 샘플 앱 아이콘·CSS·HTML은 이 하네스에서 직접 만든 것이다 |
| 원 자료의 재사용·재배포 권리 확인 | `NOT_APPLICABLE` — 공개판에 원 자료를 포함하지 않는다 |
| `[제공 기준]` 설계 수치·원칙 14항목 (글꼴 지정, 굵기·행간·자간, 간격 단위, 무그림자, 기준 프레임·최소 너비·여백·터치 영역, pill 버튼 등) | 공개 참고 자료를 참고한 값·원칙이다. 원문 인용은 없고, 출처는 위에 표시했다 |
| `[제공 기준]` 값 자체가 원 자료의 독점적 표현인지 | 판단하지 않음 (`NOT_RUN`) |

원 자료나 그 자산(파일·코드·이미지·폰트·Figma·문서 원문)을 공개판에 실제로 포함하려면, 권리를 확인하기 전까지 public 갱신을 하지 않는다.

## 7. 이 문서의 범위

- 이 문서에는 공개해도 안전한 일반 한계만 둔다.
- local 설정의 존재·상태, 공개 이력 대응표, 비공개 원본 저장소 정보, 운영·반영 절차는 비공개 원본의 운영 문서에만 둔다.
